# Smart Notifications mod: one-time toast when a law becomes ready,
# INDEPENDENT of the persistent alert's dismiss state (see
# common/alert_types/01_smart_notifications_alerts.txt's
# smart_notifications_law_commitment_alert and TODO.md).
#
# ADDED 2026-09-08 per the user: confirmed (Alert.MarkAsHidden /
# TopFrontend.UnhideAllImportantActions in gui/important_actions_list.gui,
# no dismiss-cooldown define anywhere) that important_action dismissal is
# tied to the alert's own valid trigger going false then true again, not
# to its displayed content -- so once dismissed, a DIFFERENT law becoming
# ready afterward will not bring the persistent alert back on its own,
# since "some wanted law is ready" can stay continuously true while
# WHICH law changes underneath it. This toast fires independently on each
# law's own false-to-true readiness edge, so the player always gets a
# fresh notification for a newly-ready law regardless of the persistent
# alert's dismiss state.
#
# Edge-detected via a per-law-type "already notified" variable, using the
# same static-dispatch pattern as
# common/scripted_guis/smart_notifications_law_notify_sgui.txt (effects
# cannot build a variable name dynamically). Reuses the shared
# smart_notifications_law_matches_wanted_flag / can_be_enacted /
# smart_notifications_law_ready_to_enact checks
# (common/scripted_triggers/01_smart_notifications_law_wanted_trigger.txt)
# rather than re-deriving readiness here.
on_monthly_pulse_country = {
	on_actions = {
		smart_notifications_law_ready_toast_check
	}
