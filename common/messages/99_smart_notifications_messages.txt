# Smart Notifications -- every message key this mod invents.
#
# WHY THIS FILE IS NUMBERED 99. Rows appear in the player's Message Settings
# list in the order the game reads message definitions, and Paradox reads
# common/messages/*.txt in filename order. These keys used to sit at the end of
# 00_messages.txt, but vanilla's own 01_event_messages.txt through
# 05_japan_messages.txt and unification_notifcations.txt are read AFTER it, so
# vanilla rows kept appearing below this mod's. A 99_ filename puts every
# "(SN)" row together at the end of the list.
#
# ORDER WITHIN THIS FILE is by family, and within a family by who the
# notification concerns: you, then a watched country, then everyone else.
# Deliberately NOT alphabetical -- sorting by label drops "Neither Watched"
# into the middle of the diplomatic-action family and splits the three
# diplo-play tiers apart. Keys sharing a group keep their relative order,
# because a shared row renders at whichever of its keys is read first.
#
# The 138 generated law-ready keys sit at the end; they share one group, so
# they occupy a single row however they are ordered.
#
# 00_messages.txt remains a full override of vanilla's file and still holds
# every VANILLA key this mod retunes. Only keys invented here live in this file.


# F1 -- generic diplomatic actions. Five keys, one per cell of the matrix
# in docs/watchlist-spec.md F1. Rebuilt 2026-09-09 (evening) from the
# locked spec; the previous three keys (_watched / _quiet /
# _targeting_player) encoded a different, superseded rule.
#
# WHY FIVE KEYS AND FIVE GROUPS. Two independent reasons, both binding:
#
# 1. TEXT. The `_desc` differs by whether the player is a party. Every
#    `_action_notification_desc` in vanilla's diplomacy_l_english.yml is
#    written assuming the reader IS involved ("our mutual relations",
#    "we", GetPlayer), so the at_player_* keys can reuse vanilla's full
#    specific desc verbatim, and the at_watched_*/elsewhere keys must not
#    -- they get the generic wording instead. The `_name` (the real
#    per-action title, e.g. "Kokand improving Relations") is safe for all
#    five via GetActionNotificationName.
# 2. TUNABILITY (spec D11). Player Message Settings overrides apply per
#    GROUP, not per key (CLAUDE.md), so a cell is only independently
#    adjustable if it owns its group outright. That is what lets the
#    player mute, say, the `elsewhere` row to thin the feed without
#    touching anything aimed at them -- the user's stated next goal after
#    the toast tiers are right. It also satisfies the engine's
#    no-mixed-types-per-group rule for free.
#
# The tiers below are the spec's, not a judgement call made here: an
# action earns a toast only when it is aimed at you or a watched country
# AND the actor is a watched country other than yourself. The action TYPE
# is deliberately absent from all of this -- it is unknowable at the
# moment the notification posts (docs/engine-notes.md, three separate
# ruled-out mechanisms), which is why the rule keys off WHO acted.

# ADDED 2026-09-10 per the user. The problem it solves: this mod's message
# tiers are only DEFAULTS, and a stored player setting beats a default at load
# time (docs/engine-notes.md, "stored values DO win"). So every time a release
# retunes a tier, anyone who has played before keeps the old behaviour --
# silently, with no way for the mod to detect or fix it, because
# messagetypes_custom.txt is not readable or writable from script.
#
# The only lever left is telling the player. Fired once per campaign per mod
# version, from the monthly pulse rather than on load: no on_action fires when
# a save is loaded (on_game_started_after_lobby is documented "for the first
# time for each campaign"), and variables persist inside the save, so
# "notify on every load" is not reachable. Once per version is the useful
# signal anyway -- it is exactly the moment the defaults changed.

	type = country

	texture = "gfx/interface/icons/notification_icons/influence.dds"
